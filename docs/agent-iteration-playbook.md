# Agent 迭代加速手册

本仓库的插件功能（尤其带 UI 的插件）常由「实现 agent + 验收 agent」多轮迭代完成。
这份手册来自一次真实迭代（`mcp-manager` 原型还原，2026-11-05，约 4.5 小时、6 轮实现 + 11 轮验收）的复盘，
用来把下一次同类任务压缩到 1–1.5 小时。

## 1. 那次为什么慢

时间分布：实现 6 轮 ≈ 67 分钟，验收 11 轮 ≈ 108 分钟，Lead 修复与实测 ≈ 60 分钟，等待 ≈ 30 分钟。

五个真实瓶颈：

1. **串行流水线**：实现 → 验收 → 修复 → 再验收，每轮必须等前一步结束，无法并行。
2. **验收范围漂移**：前 3 轮验的是 UI 原型一致性，后 8 轮被验收方扩展到 YAML 解析器的极端边界
   （行尾注释、`!!js` 引号、未闭合引号、嵌套 `- id:`、坏行恢复……）。问题都是真的，但已偏离主线。
3. **全文件重写**：单文件 4000 行，实现 agent 每轮都要重读大量上下文再改。
4. **机械问题占用轮次**：语法、locale 键、字面色值、API 契约这类可脚本化的检查，本应先跑脚本过滤。
5. **外部服务无快速失败**：模型网关 502 时，默认 5 次流重试 × 5 分钟空闲超时，一次失败要 8–10 分钟。

## 2. 下次的流程（按顺序执行）

### 2.1 开工前：把验收标准写成「可判定清单」

在派活之前先写清楚，三方（Lead / 实现 / 验收）看同一份：

- **范围**：只验收 `DESIGN.md` 的 N 条清单；明确写「**不扩展到 X**」（例如「不审查 YAML 解析器边界」）。
- **层级**：UI 层（视觉/交互/布局）与数据层（解析/往返/契约）**分开验收**，不要混在一轮里。
- **证据要求**：验收方每条结论必须给「文件:行号」或「选择器」；没有证据的结论不采信。
- **轮次预算**：默认 3 轮内收敛；第 3 轮仍不通过就转人工判断，不再自动循环。

### 2.2 第一步：机械检查先行（约 5 分钟）

在交给验收 agent 之前，Lead 先跑完所有确定性检查，把可脚本化的问题清零：

```bash
node --check <每个改动文件>
node scripts/check-plugins.mjs        # 仓库不变量
node -e "import('./selftest.mjs')..." # 插件自测
# 自定义：locale 键集一致性、字面色值、禁用包名、绝对路径、API 契约字段
```

这一步能挡掉本次迭代中约 1/4 的返工（locale 键、语法、颜色 token、契约不符）。

### 2.3 第二步：分层并行

```
Lead
 ├─ 实现 A（UI 层）      ──┐
 ├─ 实现 B（数据层）      ──┤ 并行
 └─ 验收 A'（上一版数据层）─┘
```

- 两个实现 agent 改**不同文件或不同函数区**，写作用域写进任务描述，避免互相覆盖。
- 验收 agent 审「上一轮已冻结的部分」，不要审正在改的部分。

### 2.4 第三步：每轮验收后立即分流

拿到问题清单后，先分类再动手：

| 类别 | 处理方式 |
|---|---|
| 机械问题（语法/键/颜色/契约） | 自己 5 分钟内改掉，不再送审 |
| 单点逻辑 bug | 派实现 agent，带最小复现输入 |
| 设计/边界争议 | Lead 直接裁决，写进 DESIGN.md，避免下一轮再吵 |
| 超出范围的新问题 | 记录到 backlog，**本轮不修** |

### 2.5 第四步：收敛判定

一轮验收后同时满足才算完成：

- 没有 P0/P1；
- P2 已记录且不阻塞；
- 所有指定检查命令通过；
- 关键路径在真实环境（浏览器/GUI）实测过一次。

## 3. 验收 prompt 模板

```
你是验收审核者，不要修改任何文件。
范围：只核对 <DESIGN.md 第 N 节> 的 M 条；不审查 <明确排除项>。
每条结论必须给「文件:行号」或「选择器」；无证据不采信。
输出：结论（通过/有条件通过/不通过）+ 逐条核对 + 新问题分级（P0/P1/P2）。
只报在代码/运行中确认过的问题；推测请标注「未验证」。
```

## 4. 本次踩过的坑（同类 UI 插件可直接复用）

**YAML 补丁层（最容易返工）**

- 行尾注释：裸标量要在 ` #` 或 `\t#` 处截断；引号内的 `#` 必须保留。
- `!!js` 表达式：序列化时统一用双引号 + JSON 转义，反序列化用 `JSON.parse` 兜底，否则表达式里的引号/换行会丢。
- 多行字符串（args 里的换行）：必须用转义标量写盘，否则回读解析失败。
- 定位行时限定「insert 列表直属缩进」，否则会误改其他插件的嵌套 `- id:`。
- 解析失败的 item 不要整组丢弃：按 id 恢复成只读行，并进 `warnings`，否则会允许同名重复创建。

**客户端状态机**

- 文本域 ↔ 数组的双向同步要加「脏标记」（`argsDirty`）：只有用户真编辑过才按行解析，否则原样保留数组。
- 普通字符串与「表达式标记」必须可区分：给字符串加转义前缀（如 `@@str:`），否则字面量会被误升级成可执行表达式。
- 无效 JSON 的阻断状态要独立于当前标签页，切换 tab 不能解除。

**弹窗与交互**

- 遮罩必须透明（不压暗下层设置面板）。
- Escape / 遮罩点击要分层：tooltip → 最上层弹窗 → 面板。
- 弹窗固定外框，内容区滚动；短视口下正文要允许收缩（`min-height: 0`），否则底部按钮被裁。
- 多选 chips 单行横向滚动，不换行、不撑高。

**仓库不变量**

- 客户端只能 `require('react')`；颜色只用 `--dsw-*` token 或基于 token 的 `color-mix`。
- locale 字典：zh/en 键集一致、值非空、每个键在字典外被 `t('key')` 引用。
- 不出现 `@deepseek-ai/` 与绝对 home 路径。

## 5. Codex 侧配置（快速失败）

`~/.codex/config.toml` 的 provider 段建议：

```toml
[model_providers.magpie]
stream_idle_timeout_ms = 90000   # 单次无数据 90 秒即放弃
stream_max_retries = 2           # 最多 3 次尝试
request_max_retries = 2
```

最坏情况 `90s × 3 = 4.5 分钟`，落在 5 分钟预算内。默认值（5 次重试 + 300 秒空闲超时）在网关故障时会拖到 10 分钟以上。

## 6. 一句话总结

**慢的不是单步，是「范围没定死 + 串行往返」。**
先定验收边界、先跑机械检查、分层并行、到轮次上限就转人工——同样的任务可以压到 1/3 时间。
