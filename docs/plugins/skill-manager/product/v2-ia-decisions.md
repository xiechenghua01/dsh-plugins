# Skills 管理模块 · v2 IA 决策单

> 版本：**v2.0-draft**
> 状态：Lead 定稿，作为 PRD v2.0 / 交互稿 v3.0 / UI 原型 v3.0 的共同输入。
> 本文件只定「结构」与「取舍」，不写完整规格与视觉细节。
> 冲突时以本文件为准；本文件改版需同步三个交付物的版本号。

---

## 1. 为什么要重做

v1 的三 Tab（已安装 / 市场 / 来源）与 8 个筛选 chips 是**按实现者的维度**组织的：

- 7 个安装位置、rank、layer、scope 优先级、预设可见性，全部是 Cordis / DSH 的内部概念；
- 用户打开这个页面的真实问题是三个：「**我装了哪些技能**」「**共享的能用哪些**」「**哪些没生效**」；
- 「来源」作为一级 Tab，把一个排查工具摆到了与「技能」「市场」同级的位置。

结论：把内部机制从 UI 撤掉，只保留用户能据此行动的信息。

---

## 2. 用户心智模型（四个箱子）

| 箱子 | 用户语言 | 对应实现 | 可写 |
| --- | --- | --- | --- |
| 我的技能 | 我自己装的 | `~/.dsh/skills`（用户级） | 是 |
| 共享技能 | 所有 Agent 共用 | `~/.agents/skills`（用户共享） | 是 |
| 项目技能 | 这个项目带的 | `<项目>/.dsh/skills` + `<项目>/.agents/skills` | 是 |
| 系统内置 | Harness 自带，不能改 | 预设内置 + 插件内置 | 否 |

分组就是**位置**，所以位置不再作为筛选维度，也不再作为行内标签。

---

## 3. 导航

- **两个 Tab**：`技能` / `市场`
- 删除「来源」一级 Tab。
  - 市场源管理 → 市场 Tab 内的「管理源」入口（抽屉）。
  - 本地路径 / 优先级等机制信息 → 不单独成页，只在分组副标题与诊断里以用户语言出现。
- 页面标题：`技能`；描述：`管理 Agent 可用的技能，看看哪些没生效。`
- 全局工具栏（技能 Tab）：搜索、排序、`+ 新建技能`、`⋯` 更多（导入、检查更新）。
- 版本号：页面不显示版本号；交付物各自标注（PRD 2.0 / 交互稿 3.0 / 原型 3.0）。

## 4. 技能 Tab

### 4.1 分组与默认展开

| 顺序 | 分组标题 | 副标题（用户语言） | 默认 |
| --- | --- | --- | --- |
| 1 | 我的技能 | 我自己装的，只在这台机器可见 | 展开 |
| 2 | 共享技能 | 所有 Agent 都能用 | 展开 |
| 3 | 项目技能 | 跟随当前项目 | 展开 |
| 4 | 系统内置 | Harness 自带，只读 | **折叠**（显示计数） |

- 空分组不渲染；全空时给空态引导（去市场看看 / 新建技能）。
- 折叠状态本地记忆。
- 已停用的技能留在原分组内，行内标记「已停用」，不单独成组。

### 4.2 筛选与排序（从 8 个减到 0 个 chips）

- **删除全部位置 chips**（全部 / 项目 / 项目共享 / 自定义 / 用户 / 用户共享 / 内置 / 已停用）。
- 保留：搜索框、排序下拉（`按名称` / `最近修改`）。
- 状态靠**徽章 + 顶部提示条**表达，不靠筛选：
  - 有更新 → 行内升级徽章 + 顶部「N 个技能有更新」
  - 未生效 → 顶部警示条「N 个技能未生效」+ 诊断入口
  - 已停用 → 行内灰显 + 「已停用」

### 4.3 行内容（信息密度）

保留：图标、名称、一行描述、状态徽章、行尾唯一按钮（更新 / 安装）、`⋯` 菜单。

**移除**：位置标签、模型可用 / 用户可调用徽章、「内置」徽章、rank、layer、provider、commit。

### 4.4 详情页

页内全宽双栏（`2fr 1fr`），保持 v2.3 布局，但内容重排：

- 左栏：名称、描述、什么时候用、正文预览（SKILL.md）、编辑入口。
- 右栏：状态、版本（如有）、作者（如有）、来源（`来自市场：X` / `本地文件`）、文件位置（可复制）、操作（停用 / 删除 / 卸载 / 更新）。
- **不含**：rank、layer、provider、commit sha、预设可见性矩阵、遮蔽链。

### 4.5 诊断（唯一保留内部信息的地方）

- 入口：顶部警示条 `查看原因`。
- 抽屉内容：一条问题 = 一个技能 + 一句人话 + 一个修复动作。
  - 示例：「`git-commit` 与另一个技能同名，当前生效的是『我的技能』里的那个」→ 操作：查看生效项 / 重命名。
  - 示例：「`ego-browser` 的文件链接已失效」→ 操作：删除失效项。
- 技术细节（路径、rank、provider）只在单条问题的「详细信息」展开里出现，默认收起。

## 5. 市场 Tab

- 保留：搜索、分类、排序、安装、更新、卸载。
- 顶部右侧：`管理源` 按钮（唯一保留「源」概念的地方）。
- 管理源抽屉：添加 / 启用停用 / 刷新 / 删除；每源显示最近检查时间与错误。
- 无源时：空态引导「添加一个技能索引源」。

## 6. 隐藏清单（v2 明确不再出现）

| 信息 | v1 位置 | v2 处理 |
| --- | --- | --- |
| 7 类安装位置 chips | 技能 Tab 筛选栏 | 删除 |
| rank 数字 | 分组头、详情 | 删除 |
| layer（preset / global） | 详情「层级」 | 删除 |
| provider（filesystem / bundled） | 详情 | 删除 |
| commit sha | 详情 | 删除 |
| 预设可见性矩阵（cordis / standard / ptc / minimal） | 详情、来源页 | 删除；仅在诊断解释「为什么没生效」时出现 |
| 同层 / 跨层遮蔽术语 | 诊断 | 改写成「与另一个技能同名」 |
| 自定义目录（custom root）管理 | 来源页 | 不提供 UI；仅在诊断里出现路径 |
| 索引 format / schema 版本 | 源管理 | 仅错误信息里出现 |
| 来源页的优先级规则说明 | 来源 Tab | 删除 |

## 7. 保留但降级

| 能力 | v1 | v2 |
| --- | --- | --- |
| 市场源管理 | 一级 Tab | 市场 Tab 内抽屉 |

## 9. 验收口径（v2 的「做对了」）

1. 打开页面 3 秒内能回答「我装了哪些技能」——默认展开前三个分组，内置折叠。
2. 页面上不出现 rank、layer、provider、commit、预设可见性中的任何一个词。
3. 全页只有一个位置概念来源：分组标题。
4. 一级导航只有两个 Tab。
5. 出现未生效技能时，一条人话 + 一个修复动作，不需要读文档。
