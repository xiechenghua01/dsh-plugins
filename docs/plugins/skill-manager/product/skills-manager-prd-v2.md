## 1. 背景与问题重述

### 1.1 v1 做成了什么

v1 用三个一级 Tab 组织页面：**已安装 / 市场 / 来源**。已安装页再按 7 类安装位置分组，并提供 8 个筛选按钮：全部、项目、项目共享、自定义、用户、用户共享、内置、已停用。详情页展示位置、优先级数字、来源实现、可见范围等机制信息。

这套结构在工程上是完整的，但对用户不是。

### 1.2 为什么 v1 的结构是错的

| 问题 | 用户心智 | v1 的做法 | 后果 |
| --- | --- | --- | --- |
| 用实现维度组织页面 | 「我装了哪些技能」 | 先让用户理解 7 类安装根，再按根查找 | 用户要先学一套目录模型，才能找到自己的技能 |
| 位置既是分组又是筛选 | 「这些技能都在我这台机器上」 | 7 个位置分组 + 8 个筛选按钮，其中「已停用」既不是位置也不是技能类型 | 同一个概念出现两次，筛选和分组互相打架 |
| 把排查工具当一级页面 | 「为什么没生效」 | 「来源」与「技能」「市场」并列 | 排查被抬高成日常入口；用户不知道什么时候该去「来源」 |
| 展示内部机制 | 「哪个版本在生效」 | 行内和详情里放优先级数字、来源实现、可见范围矩阵 | 用户看到的是实现者的问题，不是自己的问题 |

更深一层：v1 的 8 个筛选按钮把一个连续的清单切成了 8 个互斥的柜子。用户想「看看我装了什么」，必须先决定「我算哪个柜子」；用户想「哪些没生效」，却发现「没生效」只能从顶部提示条和诊断里看，筛选里没有对应项。**筛选维度没有对应用户的问题**。

### 1.3 用户真正问的三个问题

1. **我装了哪些技能？**——按「我自己装的 / 所有 Agent 共用 / 这个项目带的 / 系统自带」四个箱子回答。
2. **哪些没生效？**——需要一句人话和一个能点的修复动作，不需要读文档。
3. **共享的技能为什么被覆盖了？**——需要知道「当前用的是哪一个」，并能改名、停用或查看生效项。

### 1.4 v2 的判断

> 分类本身就是位置。位置一旦成为分类，就不该再成为筛选、标签或详情字段。内部机制从界面撤掉，只保留用户能据此行动的信息。

这不是「少显示一点」，而是把页面的组织轴从「实现者的安装根」换回「用户的箱子」。v2 的四个分类、两个一级 Tab、零个筛选按钮，都是这一判断的直接结果。

## 2. 目标与成功标准

### 2.1 产品目标

| 目标 | 一句话说明 |
| --- | --- |
| 看得懂 | 打开页面就知道自己有哪些技能，不需要理解安装根、优先级或可见范围 |
| 找得到 | 通过二级 Tab、搜索、排序找到目标技能；位置只从二级 Tab 名称获得 |
| 修得了 | 未生效时给出「一句人话 + 一个修复动作」，不要求读文档 |
| 装得上 | 从市场找到并安装一个技能不超过三步，默认落到「我的技能」 |
| 管得顺 | 新建、导入、编辑、停用、恢复、删除、卸载、更新都在两个 Tab 内完成 |

### 2.2 成功标准（与决策单 §9 对齐）

| # | 可验收标准 | 判定方法 | 对应决策单 |
| --- | --- | --- | --- |
| 1 | 打开页面 3 秒内能说出「我装了哪些技能」；默认进入「我的技能」二级 Tab，一屏只显示该分类 | 5 名未接触过该页面的用户首次打开，3 秒内能复述四个二级 Tab 名称与当前分类内至少一个技能；录屏计时 | §9.1 |
| 2 | 全页（含详情、诊断、市场、管理源、状态图标提示、空态）不出现本 PRD §14 禁用词表中的任何一个词 | 对界面文案与 locale 字典做全文检索，0 命中；设计稿走查一次 | §9.2 |
| 3 | 全页只通过四个二级 Tab 名称表达「位置」；不存在位置筛选、位置标签、位置副标题路径 | 页面与组件清单逐项核对；搜索「位置」相关控件为 0 | §9.3 |
| 4 | 一级导航只有「技能」「市场」两个 Tab，无「来源」Tab，无第三个一级入口 | 导航结构核对；任何源管理入口只能出现在市场 Tab 内 | §9.4 |
| 5 | 出现未生效技能时，诊断中每条问题都有「一句人话 + 一个修复动作」，且修复动作可在页面内完成或明确指引到唯一位置 | 用 §9 的 8 类问题做脚本化走查；每类都能不看文档说出下一步 | §9.5 |

### 2.3 辅助指标（不作为发布门槛的硬性验收，但需监测）

- 市场安装成功率 ≥ 95%（本地可控源）；失败必须有可读原因与重试。
- 诊断中「同名覆盖」「格式不合法」「链接失效」三类占未生效问题的可解释比例 100%：不允许出现「未知原因」的未生效条目。
- 停用后撤销成功率 100%（8 秒内可恢复，文件回到原分类）。
- 新建 / 导入 / 编辑保存前的校验拦截率 100%：不产生「页面说成功、Agent 看不到」的结果。

## 4. 用户与场景

### 4.1 目标用户

| 用户 | 主要诉求 |
| --- | --- |
| DSH 个人用户 | 看清自己装了什么；清理不用的；排查为什么没生效 |
| 技能作者 / 插件作者 | 本机新建、编辑、导入、分享自己的技能 |
| 团队成员 | 把项目技能放进仓库，随项目共享 |
| 跨工具用户 | 把技能放在共享目录，让多个 Agent 工具共用 |

### 4.2 核心场景

**S1 我装了哪些技能**

用户打开「技能」，默认进入「我的技能」二级 Tab，一屏只看到自己的技能。顶部一行二级 Tab 可切换到共享技能、项目技能、系统内置，每个 Tab 带数量徽章。用户不需要知道每个目录在哪，也不需要先选筛选。想找某个技能时用搜索；想找最近改过的用排序。

**S2 哪些没生效**

Tab 栏右侧出现警示图标。用户悬停看到「2 个技能未生效」，点击打开诊断抽屉，看到两条问题：一条是「`tabbit` 指向的位置已经不存在」，一条是「`my-skill` 的文件开头格式不对」。每条只有一个主要修复动作。用户点完，问题消失，图标上的提示数量减少；没有未生效技能时警示图标不再出现。

**S3 共享技能被谁覆盖**

用户把同名技能放进「我的技能」，发现 Agent 用的不是自己改的那份。打开技能详情，右侧状态写「当前生效的是『共享技能』里的版本」。诊断里给出「`code-review` 与另一个技能同名」并允许「查看生效项」或「停用其中一个」。

**S4 从市场装一个**

用户切到「市场」，搜索 `code-review`，打开详情，点「安装」。在安装对话框选择「我的技能」（默认），确认后进度完成。返回技能 Tab 后，新技能出现在「我的技能」分类的卡片列表中，并可直接「查看」；落点也可以改选「共享技能」或「项目技能」。

**S5 停用一个不用的**

用户在「我的技能」分类中找到不用的技能，点卡片右侧的 `⋯` 菜单选「停用」。卡片整体降对比并保留「已停用」徽章，底部提示 8 秒内可撤销。文件没有删除，之后可以恢复；已停用的技能仍留在原分类，不会跑到单独的组里。

**S6 项目里带一个团队技能**

用户在「项目技能」二级 Tab 看到随仓库带来的技能。想追加一个时，从市场安装并选择「项目技能」，完成后提示该技能会跟随项目目录；撤销或删除只影响这个项目。

**S7 新建并验证格式**

用户点「+ 新建技能」，填写名称、描述、什么时候用、正文，选择保存到「我的技能」。保存前页面校验名称格式与必填项；校验不通过时提示具体原因，不写文件。保存成功后新卡片出现并高亮。

## 5. 产品形态与导航

### 5.1 形态与入口

| 项 | 规格 |
| --- | --- |
| 形态 | 左侧栏入口 + 中央内容区全屏面板，与 Plugins、自动化任务同级 |
| 侧栏入口 | 图标 + 「技能」；折叠时保留图标与悬停名称 |
| 入口标识 | `sidebar.panellist`，`id = skill-manager`，`order = 20`（实现备注） |
| 主面板槽位 | `main`，key 为 `skill-manager`（实现备注） |
| 路由前缀 | `/skill-manager/api`（实现备注） |
| 页面标题 | `技能` |
| 页面描述 | `管理 Agent 可用的技能，看看哪些没生效。` |

入口与槽位的实现约束以 `docs/plugins/skill-manager/design/implementation-contract.md` 为准；本文只约定用户看到的名称与位置。

### 5.2 一级导航

两个 Tab，顺序固定：

1. **技能**（默认）
2. **市场**

「来源」不再是一级 Tab。市场源管理入口位于市场 Tab 顶部右侧的「管理源」图标按钮，点击打开**居中弹窗**（支持拖动排序）。本地路径、优先级、来源实现等信息不再有独立页面。

### 5.3 二级 Tab（技能 Tab）

技能 Tab 内部再放一行二级 Tab，与一级 Tab 使用同一套视觉，顺序固定：

| 顺序 | 二级 Tab | 计数 | 空态 |
| --- | --- | --- | --- |
| 1 | 我的技能 | 数字徽章 | 「还没有自己的技能，从市场装一个或新建一个」 |
| 2 | 共享技能 | 数字徽章 | 「这里放所有 Agent 共用的技能」 |
| 3 | 项目技能 | 数字徽章 | 「当前项目还没有技能」 |
| 4 | 系统内置 | 数字徽章 | 「Harness 自带的技能都正常」 |

规则：

- **一屏只显示一个分类**；不再有可折叠的分类分组头，也不再显示分类副标题，副标题信息并入空态与详情。
- 每个二级 Tab 内部**再按来源分组**：每个市场源一组，「本地创建」一组固定排最后；组头不可折叠。系统内置 Tab 不按来源分组。详见 §7.1.1。
- 二级 Tab 记忆上次选择；默认 `我的技能`。
- 计数来自该分类的列表总数，与搜索、排序无关。
- 搜索时**跨分类搜索**；命中后自动切到第一个有结果的分类，并保持搜索词；搜索结果在分类内展示，分组随之过滤。
- 分类为空时整屏显示该分类的空态，不给「切到别的分类」以外的干扰。
- 二级 Tab 只在技能 Tab 出现；市场 Tab 没有二级 Tab。
- 无项目上下文时，「项目技能」Tab 仍然显示，使用空态「当前项目还没有技能」。

> 与 v2.0 的差异：v2.0 的「默认展开前三组、系统内置折叠」规则作废。

### 5.4 工具栏（技能 Tab）

工具栏只有一行控件：**搜索 · 排序 · 新建 / 导入 / 检查更新 三个图标按钮**。

| 控件 | 形态 | 悬停提示 | 行为 |
| --- | --- | --- | --- |
| 搜索 | 输入框 | — | 在「技能」Tab 内跨分类搜索名称、描述、什么时候用；有输入时显示清除 |
| 排序 | 下拉 | — | `按名称` / `最近修改` / `按来源`；分类顺序不变，排序只作用于当前分类内 |
| 新建 | 图标按钮 | `新建技能` | 打开新建对话框；默认落点「我的技能」 |
| 导入 | 图标按钮 | `导入技能` | 打开导入对话框 |
| 检查更新 | 图标按钮 | `检查更新` | 检查所有源的更新并刷新列表；执行时按钮转圈，完成后提示 `已检查 N 个源，M 个技能可更新` |

规则：

- **删除工具栏 `⋯` 菜单**。新建、导入、检查更新三个动作直接以图标呈现，悬停 300ms 显示名称。
- **「检查更新」与「刷新列表」合并为一个动作**。两者读取的都是同一批源与本地技能状态：分成两个入口时，用户不知道该点哪个，还容易以为「刷新列表」会顺带发现新版本。合并后一个动作同时完成「重新拉取列表」和「检查更新」；按钮转圈表示进行中，结束后用一条汇总提示回答结果。
- 排序下拉保留；检查更新不重置搜索与排序。
- 图标按钮只放图标不放文字；尺寸、间距与图标大小见交互稿与原型。

市场 Tab 的工具栏按 §10 单独定义：搜索 · 排序 · `检查更新` 图标按钮 · `管理源` 图标按钮；其中检查更新与技能 Tab 是同一个动作。

### 5.5 Tab 栏右侧状态图标

v2.0 的顶部警示条与更新细条删除，改为一级 Tab 栏右侧、与「技能 / 市场」同一行右对齐的两个图标。只有图标没有文字；数量为 0 时不显示图标：

| 图标 | 含义 | 出现条件 | 悬停提示（300ms） | 点击 |
| --- | --- | --- | --- | --- |
| 警示（三角） | 有技能未生效 | 未生效数量 > 0 | `{n} 个技能未生效` | 打开诊断抽屉 |
| 向上箭头（带点） | 有技能可更新 | 可更新数量 > 0 | `{n} 个技能可以更新 · 上次检查 {when}` | 触发更新流程 |

- Tab 栏右侧最多出现这两个图标；两者都不满足条件时该区域为空，不占位、不显示空条。
- 上次检查失败不新增第三个图标：失败原因在「管理源」弹窗与诊断的「来源不可达」中呈现，更新图标的悬停提示仍显示上次检查时间。
- 详情页内的更新按钮保留，不受此处改动影响。

| 技能详情返回位置 | 返回列表时回到原来的分类与卡片位置 |

## 7. 技能 Tab 规格

### 7.1 四个二级 Tab

| 顺序 | 二级 Tab | 空态（用户语言） | 可写 | 用户理解 |
| --- | --- | --- | --- | --- |
| 1 | 我的技能 | 「还没有自己的技能，从市场装一个或新建一个」 | 是 | 个人专用 |
| 2 | 共享技能 | 「这里放所有 Agent 共用的技能」 | 是 | 跨工具共用 |
| 3 | 项目技能 | 「当前项目还没有技能」 | 是 | 随仓库走 |
| 4 | 系统内置 | 「Harness 自带的技能都正常」 | 否 | 不能改 |

规则：

- **分类就是位置**。一个技能只属于一个二级 Tab；不在卡片、详情重复显示位置。Tab 内的来源分组只是组织结构，不是新的分类。
- **一屏只显示当前分类**；没有可折叠的分类分组头，也不显示分类副标题。
- 分类为空时整屏显示该分类的空态；不把其他分类拼在同一屏。
- 已停用的技能**留在原分类**，卡片整体降对比并保留「已停用」徽章；不单独成组。
- 系统内置卡片没有开关、删除、编辑；只保留 `⋯` 中的查看与复制路径。
- 无项目上下文（未打开项目）时，「项目技能」Tab 仍然显示，使用空态「当前项目还没有技能」。
- 二级 Tab 的数量徽章是该分类全部技能数（含已停用），不另设「已停用」计数入口。

#### 7.1.1 来源分组

每个二级 Tab 内部再按**来源**分组，组头顺序与市场页一致：

| 分组 | 判定 | 组头 |
| --- | --- | --- |
| 市场源（每个源各一组） | 安装记录里的来源属于该源 | 源名称 + `N 个技能` |
| 本地创建 | 没有市场来源（手工新建、导入、手动放置） | `本地创建` + `N 个技能` |

规则：

- 组头顺序 = 市场页的源顺序；「本地创建」固定排在最后。
- 空组不渲染；搜索后命中为空的分组也不渲染。
- 技能记录的来源已从管理源删除时，该技能归入「本地创建」，详情里的来源显示「原来源已移除」。
- 组头不可折叠；组内仍是两列卡片（见 §7.3）。
- **系统内置 Tab 不按来源分组**，直接显示两列卡片（它们全部来自 Harness 本身）。
- 搜索仍跨分类；进入命中分类后，分组随之过滤。
- 组头只表达来源名称与数量，不显示路径、优先级或技术信息。

### 7.2 搜索与排序

| 项 | 规格 |
| --- | --- |
| 搜索范围 | 名称、描述、什么时候用；不搜正文与路径 |
| 防抖 | 交互稿定义；输入后列表即时过滤，无结果给搜索空态 |
| 搜索与分类 | **跨分类搜索**；命中后自动切到第一个有结果的分类并保持搜索词；结果在该分类内展示 |
| 排序 | `按名称` / `最近修改` / `按来源`；只影响当前分组内卡片顺序，不改变分类顺序，也不改变组头顺序 |
| 默认排序 | 按名称 |
| 筛选 | **无**。不提供位置、状态、来源筛选按钮 |

状态表达不通过筛选，通过三处：Tab 栏右侧状态图标、卡片徽章、卡片降对比。

### 7.3 两列卡片

**网格**

- 技能页与市场页都使用两列卡片；卡片间距一致。
- 内容区宽度不足以并排两张卡片时退化为单列；退化阈值由交互稿按 DSH Discover 的最小卡宽定义。
- 两列在常规桌面窗口下始终成立，不因卡片数量变化而改变列数。

**卡片结构**

```
┌──────────────────────────────────┐
│ ┌────┐  名称  [徽章]   ┌───┐ ┌──────┐ │
│ │图标│  描述（最多 2 行）│ ⋯ │ │ 更新 │ │
│ └────┘                  └───┘ └──────┘ │
└──────────────────────────────────┘
            右侧水平：⋯ 在左，主按钮在右
```

- 左侧：技能图标、名称、状态徽章、最多两行描述；超出省略。
- 右侧：**水平排列两个控件，同一行、右对齐**——`⋯` 在左，唯一主按钮在右（有更新时 `更新`；市场卡片可为 `安装` / `已安装`）。
- 没有主按钮时只显示 `⋯`，仍位于右侧同一位置。
- `⋯` **默认隐藏**，只保留占位；卡片悬停、键盘聚焦到 `⋯` 时淡入。隐藏与显示**不引起布局位移**，卡片文字与按钮位置保持稳定。
- 主按钮在有更新或可安装时始终可见。
- 卡片整体可点击进入详情；右侧按钮与 `⋯` 阻止冒泡。
- 卡片高度统一；描述最多 2 行，超出省略。
- 卡片视觉对齐 DSH Discover 卡片，具体样式见交互稿 v3.2 / 原型 v3.2。

**卡片内容**

| 区域 | 内容 | 规则 |
| --- | --- | --- |
| 左 | 图标 | 技能自定义图标；无则用来源类型字形 |
| 主 | 名称 | 与文件中的技能名一致 |
| 主 | 描述 | 最多两行，超出省略；无描述时显示「没有描述」 |
| 主 | 徽章 | 仅保留：`已停用`、`未生效`、`有更新`（带版本号） |
| 右 | 唯一主按钮 | 有更新时「更新」；其余技能无主按钮 |
| 右 | `⋯` 菜单 | 查看详情、编辑、复制路径（有路径时）、停用 / 恢复、删除 / 卸载 |

明确移除：位置标签、模型可用 / 用户可调用徽章、「内置」行内徽章、优先级数字、来源实现、提交号、预设可见性。

### 7.4 卡片状态

| 状态 | 卡片内表达 | Tab 栏表达 | 可执行 |
| --- | --- | --- | --- |
| 正常 | 正常显示 | — | 打开、编辑、停用、删除 |
| 已停用 | 整体降对比 + `已停用` 徽章 | — | 恢复、删除 |
| 未生效 | 名称旁问题标记 + `未生效` | 警示图标（悬停提示数量） | 查看原因、编辑、删除 |
| 有更新 | `有更新` 徽章（含新版本号） | 更新图标（悬停提示数量与检查时间） | 更新、打开 |
| 只读（系统内置） | 无写操作按钮 | — | 打开、复制路径（有路径时） |

### 7.5 空态

| 场景 | 文案 | 出口 |
| --- | --- | --- |
| 我的技能为空 | `还没有自己的技能，从市场装一个或新建一个` | 「去市场看看」；「新建技能」 |
| 共享技能为空 | `这里放所有 Agent 共用的技能` | 无（可切换到其他二级 Tab） |
| 项目技能为空 | `当前项目还没有技能` | 无（可切换到其他二级 Tab） |
| 系统内置为空 | `Harness 自带的技能都正常` | 无 |
| 搜索无结果 | `没有匹配「{关键词}」的技能` | 清除搜索 |

空态不展示技术路径与目录说明；「技能应该放哪里」由新建对话框的落点选择回答。

## 8. 技能详情规格

### 8.1 形态与进入方式

- 点击技能卡片进入**页内详情**，不使用右侧抽屉。
- 顶部保留「返回」；返回后回到原分类、原滚动位置。
- 详情页仍是「技能」Tab 内的视图，不产生新的一级导航，也不改变 Tab 状态。
- 详情页不显示版本号、优先级、层级、来源实现、提交号、可见范围矩阵或同名覆盖链。

### 8.2 页面结构

| 区域 | 内容 |
| --- | --- |
| 返回栏 | `返回`；右侧显示当前状态（生效中 / 已停用 / 未生效） |
| 头部 | 图标、名称、版本（市场安装时有）、`有更新` 徽章（有更新时） |
| 左栏（主） | 描述；什么时候用（有则显示）；正文预览（`SKILL.md`）；编辑入口 |
| 右栏（侧） | 状态说明；版本（如有）；作者（如有）；来源；文件位置；操作 |

左栏承载「这个技能是什么、怎么用、内容是什么」；右栏承载「它在哪、现在什么状态、能对它做什么」。两栏均为页面内滚动，操作区不悬浮遮挡正文。

### 8.3 左栏字段

| 字段 | 显示规则 |
| --- | --- |
| 名称 | 与文件中的技能名一致；不显示文件名后缀 |
| 描述 | 完整显示，不截断 |
| 什么时候用 | 有则显示，无则整块不显示 |
| 正文预览 | 显示 `SKILL.md` 正文（不含文件开头的格式信息）；可滚动；长文不折叠到不可读；可展开为独立预览弹窗（宽度见 §11） |
| 编辑入口 | 可写技能显示「编辑」；系统内置不显示 |

编辑规则：

- 点击「编辑」打开原文编辑弹窗（宽度见 §11），保存前校验名称、描述、文件格式与正文非空。
- 校验失败在编辑区内提示具体原因，不写文件；成功保存后回到预览并提示「已保存」。
- 文件被外部修改时，提示「文件已被外部修改，请重新打开后再改」，不覆盖用户的外部改动。

### 8.4 右栏字段

| 字段 | 显示规则 |
| --- | --- |
| 状态 | `生效中` / `已停用` / `未生效`；同名覆盖时补充「当前生效的是『共享技能』里的版本」 |
| 版本 | 仅市场安装的技能显示；本地新建技能无版本，不显示空行 |
| 作者 | 仅市场索引提供时显示 |
| 来源 | 市场安装：`来自市场：{源名}`；本地文件：`本地文件`；系统内置：`Harness 自带` |
| 文件位置 | 完整路径，可复制；系统内置无路径时显示「由 Harness 内置提供，没有本地文件」 |
| 操作 | 按 §8.5 的技能类型给出按钮 |

「文件位置」是界面中唯一允许出现完整路径的地方（诊断「详细信息」除外）。卡片、二级 Tab、状态图标提示均不显示路径。

### 8.5 操作矩阵

| 技能类型 | 主操作 | 次操作 | 不可用说明 |
| --- | --- | --- | --- |
| 我的技能 / 共享技能 / 项目技能（本地） | `停用`（已停用时为 `恢复`） | `删除` | — |
| 市场安装 | `更新`（有更新时）/ `停用`或`恢复` | `卸载` | — |
| 系统内置 | 无 | 无 | 显示「Harness 自带，不能修改」 |

- 停用：立即执行，底部提示可撤销；文件保留，可恢复。
- 删除：二次确认，说明删除该技能及其资源文件、不可撤销。
- 卸载：二次确认，说明删除安装内容与安装记录，不影响其他技能；可选保留备份。
- 更新：先显示「当前版本 → 新版本」与本地修改警告，再执行。
- 所有失败在操作区就地提示原因，不把错误只做成一条短暂提示。

## 9. 诊断规格

### 9.1 入口与结构

- **入口**：一级 Tab 栏右侧的警示图标（三角）；悬停 300ms 显示 `{n} 个技能未生效`，点击打开诊断抽屉。未生效数量为 0 时图标不出现。
- **形态**：右侧抽屉；不新开页面，不占一级导航。抽屉内容与 v2.0 一致。
- **结构**：
  1. 摘要：`N 个技能未生效 · M 个需要留意` + 上次检查时间 + `重新检查`。
  2. 「未生效」段：每条 = 一个技能 + 一句人话 + 一个修复动作。
  3. 「需要留意」段：不阻断使用、但会影响体验的问题（文件过大、来源不可达）。
  4. 每条问题的「详细信息」默认收起，展开后才显示路径等技术细节。
- **无问题**：显示「全部正常，没有发现问题」，不显示空列表。
- **部分检查失败**：已完成的问题照常显示；失败部分显示「有些位置这次没检查到」+ `重试`，不把整页判为错误。

> 下表的问题类型名只用于产品、设计、实现三方对齐，**不是界面文案**。界面只出现「用户看到的一句话」。

### 9.2 问题分类与文案对照

| 类型（内部对齐） | 用户看到的一句话 | 一个修复动作 | 是否计入「未生效」 |
| --- | --- | --- | --- |
| 同名覆盖 | 「`{name}` 与『{分类名}』里的另一个技能同名，现在生效的是后者。」 | `查看生效项`（同时提供 `停用其中一个`） | 是 |
| 文件格式不合法 | 「`{name}` 的文件开头格式不对，Agent 读不到它。」 | `打开文件修正` | 是 |
| 链接失效 | 「`{name}` 指向的位置已经不存在了。」 | `删除失效项` | 是 |
| 没有读取权限 | 「`{name}` 所在的文件夹打不开，可能是权限问题。」 | `打开所在目录`（按提示改权限后 `重新检查`） | 是 |
| 名称不合规 | 「`{name}` 的名字不符合规则：只能用小写字母、数字和连字符。」 | `重命名` | 是 |
| 文件过大 | 「`{name}` 的内容比较大，加载会变慢，有些 Agent 可能读不全。」 | `查看并精简正文` | 否（需要留意） |
| 来源不可达 | 「`{name}` 来自市场源『{源名}』，这个源暂时连不上；已安装的版本仍然能用，只是暂时不能检查更新。」 | `去管理源处理` | 否（需要留意） |
| 文件夹不存在或读不到 | 「存放 `{name}` 的文件夹这次没能读到，Agent 现在看不到它。」 | `重试` | 是 |

> 实现备注：「文件格式不合法」对应旧版的 frontmatter 校验失败（缺少名称或描述、文件开头格式错误、使用已不支持的写法）。该英文术语只用于三方对齐，不得出现在界面。

补充规则：

- **同名但生效的是用户自己的版本**（例如用户版本盖住系统内置版本）不算「未生效」，在详情状态里说明即可，不计入未生效数量，也不触发警示图标。
- **来源不可达**不代表已安装技能失效，不能混入「N 个技能未生效」；它只影响更新检查。
- 一个问题卡只给**一个**主按钮（实心样式）；至多再给一个**弱化**的排查动作（如「打开所在目录」），其余动作放进卡片菜单或「详细信息」，避免用户面对一排同等权重的按钮不知道先点哪个。
- 修复动作只做用户明确选择的改动，不做自动改名、自动删除、自动改格式。
- 修复后立即重新检查该条；问题消失则从抽屉移除并更新计数；修复失败就地说明原因。

### 9.3 「详细信息」内容

默认收起，仅在单条问题内展开。允许包含：

- 技能文件的完整路径；
- 判定原因的技术描述（例如「文件第一行不是 `---`」）；
- 涉及的两个同名技能各自的位置与路径；
- 来源地址与上次检查时间（仅来源不可达）。

不允许包含：优先级数字、层级名、来源实现名、提交号、预设可见性矩阵。这些信息对用户没有可执行价值；如排障确需，放在实现日志中，不进入界面。

### 9.4 诊断文案示例

> **同名覆盖**
> `code-review` 与『我的技能』里的另一个技能同名，现在生效的是后者。
> [查看生效项]
> 详细信息：两个文件的位置 …
>
> **链接失效**
> `tabbit` 指向的位置已经不存在了。
> [删除失效项]

> 说明：`{分类名}` 取技能所在分类（我的技能 / 共享技能 / 项目技能）。「项目技能」是 `<项目>/.dsh/skills` 与 `<项目>/.agents/skills` 合并后的分类，两个位置同名时统一说「项目里的另一个技能」，不暴露两者的优先级。

## 10. 市场 Tab 规格

### 10.1 按源分区块的列表

市场 Tab **不设二级 Tab**，改为按市场源分区块；每个源一个区块，区块内为两列卡片。

| 区域 | 规格 |
| --- | --- |
| 顶部 | 搜索、分类、排序 |
| 右上 | `管理源` 图标按钮（源管理的唯一入口，悬停提示 `管理源`） |
| 搜索 | 搜技能名称、标题、描述；300ms 防抖；跨源搜索，命中结果仍按源分区块展示 |
| 分类 | 来自各源索引的标签；`全部` + 高频标签，最多 12 个 |
| 排序 | `推荐` / `最近更新` / `按名称`；只在每个源区块内生效 |
| 数据范围 | 聚合所有已启用的源，按源顺序分区块；**不提供「全部源」合并视图，也不提供源筛选** |
| 区块标题 | 源名称、该源技能数、该源的 `⋯`（刷新 / 删除；排序在管理源弹窗内拖动） |
| 卡片 | 每源两列卡片；图标、名称、版本、作者（有则）、最多两行描述、右侧水平操作 |
| 卡片操作 | `⋯` 在左、主按钮在右，同一行；`⋯` 默认隐藏，悬停或聚焦时显示，不引起布局位移；未安装 `安装`、已安装 `已安装`（点击进入详情）、有更新 `更新` |
| 来源标识 | 卡片不再重复源名（区块标题已表达）；详情显示「来自市场：{源名}」 |

状态与空态：

| 场景 | 表达 | 出口 |
| --- | --- | --- |
| 没有任何源 | `还没有添加技能索引源` | `添加源` |
| 某个源为空 | `这个源暂时没有技能` | 该源 `⋯` → `刷新`；或 `管理源` |
| 源不可达 | `有些源暂时连不上，先显示上次的结果` | `管理源` / `重试` |
| 搜索无结果 | `没有匹配「{关键词}」的技能` | 清除搜索 |
| 加载中 | 状态文字 + 区块骨架 | — |

#### 10.1.1 源排序

- 管理源弹窗里每个源可**拖动排序**：整行可拖动，拖动时显示插入位置指示线，放下后立即重排并持久化。
- **键盘替代**：源行获得焦点后 `Alt+↑` / `Alt+↓` 移动，覆盖无法使用拖动的场景。
- 不再提供上移 / 下移箭头按钮。
- **排序即优先级**：排在前面的源，其技能在市场中排在前面；不同源出现同名技能时，以排在前面的源为准。
- 该顺序同样用于技能列表「按来源」排序时的先后，以及技能 Tab 内来源分组的组头顺序。
- 排序持久化在本地状态里，重启后保留。
- 新增源默认排最后。
- 调整顺序后，市场区块顺序、技能页来源分组顺序与「按来源」排序结果同步变化；不需要用户重新搜索或刷新。

### 10.2 市场技能详情

页内视图，保留「返回」。内容：

| 区块 | 内容 |
| --- | --- |
| 头部 | 图标、名称、版本、作者；右侧安装 / 更新 / 已安装按钮 |
| 描述 | 市场提供的完整描述 |
| 元信息 | 来源（源名）、许可证、主页、更新时间、最低 Harness 版本；无值不显示 |
| README 摘要 | 索引提供时显示；否则只显示描述 |
| 文件清单 | 文件名称与大小；不显示校验值等技术字段 |
| 已安装状态 | 安装位置（用四个箱子名）、已装版本、安装时间、是否有本地修改 |

- 不显示提交号、索引格式版本、文件校验值。
- 「安装位置」一律使用用户语言：我的技能 / 共享技能 / 项目技能；不显示路径与优先级。
- 详情页的「来源」只写市场源名称，不写实现细节。

### 10.3 安装

三步内完成：

| 步骤 | 内容 | 默认 |
| --- | --- | --- |
| 1. 选择位置 | 我的技能 / 共享技能 / 项目技能 | 我的技能 |
| 2. 确认 | 技能名、版本、位置；同名冲突时选择 `覆盖` / `跳过` / `换位置` | — |
| 3. 完成 | 进度、成功提示、`查看技能` | — |

规则：

- 项目不可用时，「项目技能」不可选，并说明「当前没有打开项目」。
- 同名冲突必须显式选择，不默认覆盖。
- 安装过程中可取消；取消后不留下半安装内容。
- 失败原因用用户语言：源连不上、文件校验失败、磁盘空间不足、没有写入权限；给 `重试` 或 `换位置`。
- 成功后技能出现在对应分类的卡片列表中，卡片高亮；不自动打开详情。
- 安装默认使用最新兼容版本，不要求用户额外选版本；详情可显示当前安装的版本。

### 10.4 更新

- **检查可以自动，写入必须手动**：后台定期检查，只在界面提示「有更新」，不自动下载、不自动覆盖。
- 触发：打开页面时读取检查结果；Tab 栏右侧的更新图标可触发更新流程；工具栏的「检查更新」图标按钮可手动重查，该动作同时刷新列表。
- 更新前展示：当前版本 → 新版本；本地文件被改过时提示「本地文件已修改，更新会覆盖这些修改」。
- 确认后执行；失败回滚到更新前版本，并就地说明原因。
- 更新成功后保留当前列表、搜索与排序。

### 10.5 卸载

- 入口：已安装的市场技能详情、卡片 `⋯` 菜单。
- 确认文案说明：删除该技能与安装记录；不影响其他技能；可选保留备份。
- 卸载后该技能从技能 Tab 消失，市场卡片恢复为「安装」。
- 卸载不是「停用」：不提供恢复，除非选择了保留备份。

### 10.6 管理源弹窗

管理源由右侧抽屉改为**居中弹窗**：宽度 `min(720px, 100vw - 32px)`，最大高度 `min(720px, 100vh - 96px)`，列表区内部滚动。源列表内容较多，取 DSH 大内容弹窗档，并强制保留视口余量，保证在 1280 / 1024 / 800 宽窗口下都不溢出。

| 区域 | 内容 |
| --- | --- |
| 标题 | `管理源` + 源数量徽章 + 关闭 |
| 说明 | `排序即优先级：排在前面的源，其技能在市场中排在前面。` |
| 列表 | 按当前源顺序排列；每行显示拖动手柄、状态点、源名称、技能数、启用开关、刷新、删除 |
| 单条操作 | `刷新`、`启用` / `停用`、`删除`；调整顺序用拖动整行 |
| 排序 | **拖动排序**：整行可拖动，拖动时显示插入位置指示线，放下后立即重排并持久化 |
| 键盘替代 | 源行获得焦点后 `Alt+↑` / `Alt+↓` 移动；不提供上移 / 下移箭头按钮 |
| 添加源 | 输入索引地址 → `校验` → 预览（名称、技能数、示例条目）→ `保存`；新增源默认排最后 |
| 错误 | 每条源就地显示原因（连不上、地址无效、格式不正确、内容过大），不弹全局错误 |
| 空态 | `还没有添加技能索引源` + `添加源` |
| 信任提示 | 首次添加时说明「该源由第三方提供，安装前请确认来源可信」 |

规则：

- 状态点悬停 300ms 显示该源当前状态（`正常` / `连不上` / `检查中`），不使用只靠颜色表达状态。
- 删除源不影响已安装技能；已安装技能保留「来自市场：X」的来源信息，之后不再检查更新。
- 停用源后不再参与市场列表与更新检查；已安装技能仍可用。
- 源不可达时保留上次成功结果并标注「上次结果」，不把市场清空。
- 同一条源不重复添加；地址变化需重新校验。
- 弹窗内不出现索引格式版本、校验规则编号、JSON 字段路径等内部信息；只在错误原因里给出用户能理解的一句话。

## 11. 弹窗规格

> 本节只约定宽度与使用场景；圆角、边框、内部间距、按钮区高度等视觉规格见 `v2-2-review-decisions.md` §5、`v2-1-review-decisions.md` §6 与交互稿 v3.2，不在本文重复。

| 弹窗 | 宽度 | 使用场景 |
| --- | --- | --- |
| 新建技能、导入技能、添加源 | `min(488px, 100%)` | 表单类弹窗：有多个输入项，需要稳定的阅读宽度 |
| 更新确认、卸载确认、删除确认 | `min(480px, 100vw - 32px)` | 确认类弹窗：只读正文 + 两个按钮，窄于表单 |
| 管理源 | `min(720px, 100vw - 32px)` | 大内容类弹窗：源列表内容多，取大弹窗档并强制视口余量 |
| 编辑原文、SKILL.md 预览 | `min(720px, 100%)` | 大内容类弹窗：需要同时显示较长的技能正文 |

规则：

- 四档宽度对齐 DSH 现有弹窗实测值；与其他 DSH 弹窗并排时不显突兀。
- 表单弹窗使用 488px，确认弹窗使用 480px，管理源与编辑 / 预览类使用 720px；不再使用 v2.0 的 560px / 640px 自定宽度。
- **视口余量与高宽上限**：管理源宽度上限 720px，且左右至少各留 32px；高度上限 `min(720px, 100vh - 96px)`，超出时列表区内部滚动，标题与底部操作保持可见。1280 / 1024 / 800 宽窗口下均不横向溢出。
- 窗口宽度不足时，弹窗宽度按上表的 `min(...)` 收窄，不出现横向滚动。
- 同一场景不出现两种宽度；新增弹窗先归入上述档位之一。

## 12. 隐藏清单（实现备注）

> **本节是实现备注，只用于核对「哪些旧概念必须从界面消失」。表中的术语不得出现在任何用户可见文案中；出现即视为验收失败。**

| 信息 | v1 位置 | v2 处理 | 为什么隐藏 |
| --- | --- | --- | --- |
| 折叠分组头 / 分组副标题 | 技能 Tab | 删除；改为四个二级 Tab，一屏一个分类 | v2.0 的折叠分组规则作废；折叠头多一次点击，一屏多分类不符合首轮评审结论 |
| 源筛选 / 全部源合并视图 | 市场 Tab | 不提供；市场按源分区块，顺序即优先级 | 源筛选把「顺序」问题重新变回筛选问题；合并视图丢失来源上下文 |
| 顶部警示条 / 更新细条 | 技能 Tab | 删除；改为 Tab 栏右侧两个状态图标 | 横幅占空间，与 DSH 不一致 |
| 行式列表 | 技能 Tab、市场 Tab | 删除；改为两列卡片 + 右侧水平操作 | 首轮评审要求两列；行式列表的操作位置与卡片结构不匹配 |
| 工具栏 `⋯` 菜单 | 技能 Tab 工具栏 | 删除；新建 / 导入 / 检查更新改为三个图标按钮 | 三个动作都是常用入口，菜单多一层点击；图标按钮更直接 |
| 单独的「刷新列表」 | 技能 Tab 工具栏 | 删除；与「检查更新」合并为一个动作 | 两者读取同一批源与本地状态，分设入口会让用户犹豫点哪个 |
| 源排序的上下箭头 | 管理源 | 删除；改为拖动排序，键盘用 `Alt+↑` / `Alt+↓` | 箭头逐格移动效率低；拖动直接表达「顺序即优先级」 |
| 自定弹窗宽度（560 / 640px） | 各对话框 | 删除；改用 480 / 488 / 720 三档 | 与 DSH 现有弹窗不一致 |
| 7 类安装位置 chips | 技能 Tab 筛选栏 | 删除 | 位置已是分类，再做筛选等于让用户重复分类；8 个按钮没有对应用户问题 |
| rank 数字 | 分组头、详情 | 删除 | 是内部优先级实现，用户无法据此行动；同名问题改用「当前生效的是哪一个」表达 |
| layer（preset / global） | 详情「层级」 | 删除 | 层级是实现概念，用户只关心「我的 / 共享 / 项目 / 内置」 |
| provider（filesystem / bundled） | 详情 | 删除 | 来源实现与用户操作无关；界面只说「本地文件 / 来自市场 / Harness 自带」 |
| commit sha | 详情 | 删除 | 不可读、不可操作；版本号已足够回答「装的是哪一版」 |
| 预设可见性矩阵（cordis / standard / ptc / minimal） | 详情、来源页 | 删除；仅在诊断解释「为什么没生效」时出现 | 用户不按预设思考；矩阵只增加理解成本，且四个预设名对用户无意义 |
| 同层 / 跨层遮蔽术语 | 诊断 | 改写成「与另一个技能同名」 | 「遮蔽」是机制词，用户需要的是「谁在生效、我该怎么做」 |
| 自定义目录（custom root）管理 | 来源页 | 不提供 UI；仅在诊断里出现路径 | 这是高级配置，日常用户不应为此承担认知负担；需要时在诊断详情可见 |
| 索引 format / schema 版本 | 源管理 | 仅错误信息里出现 | 用户不需要知道索引规范版本；错误只需说明「格式不正确」 |
| 来源页的优先级规则说明 | 来源 Tab | 删除 | 规则说明是文档内容，不是页面任务；页面应给动作而非讲义 |

补充：v1 的「模型可用 / 用户可调用」徽章、「内置」行内徽章、「已停用」独立分组也一并移除，分别以卡片差异、系统内置 Tab 内只读、原分类降对比替代。v2.0 的折叠分组、分组副标题与顶部状态条同样作废。v2.1 的工具栏 `⋯` 菜单、单独的「刷新列表」与源排序上下箭头同样作废，不得在实现或交互稿中保留。

## 13. 跨模块规则

### 13.1 命名与校验

| 项 | 规则 | 用户可见提示 |
| --- | --- | --- |
| 名称 | 小写字母、数字、连字符；不能以连字符开头或结尾；不超过 64 个字符 | `名称只能使用小写字母、数字与连字符` |
| 重名 | 同一分类内不可重名；跨分类允许同名，但需提示当前生效的是哪一个 | `这个分类里已有同名技能` |
| 描述 | 必填；卡片最多两行显示，详情完整显示 | `请填写一句话描述` |
| 什么时候用 | 选填，最多 200 字 | `最多 200 字` |
| 正文 | 必填，不能为空 | `请填写技能正文` |
| 文件布局 | 每个技能是一个目录内的 `SKILL.md`，或根目录下的一个 `.md` 文件；不扫描更深层级 | 新建 / 导入时由系统落位，用户无需理解 |
| 文件格式 | 文件开头需有名称与描述的元信息块；格式不合法会导致 Agent 读不到 | `技能文件格式不正确：{原因}` |
| 写入时机 | 新建、导入、编辑保存、市场安装前均先校验；不合法直接阻止 | 不允许「提示成功但实际未生效」 |

- 校验规则必须与 Harness 实际读取规则一致；页面通过、Agent 读不到视为缺陷。
- 校验失败时必须说明「哪一项不对」，不能只显示「保存失败」。
- 名称不能自动「修正」成合法值；给出建议值，由用户确认。

### 13.2 三种「移除」的区别

| 动作 | 用户语言 | 实际发生什么 | 可恢复 | 用在哪 |
| --- | --- | --- | --- | --- |
| 停用 | `停用` / `恢复` | 技能从 Agent 可见范围移出，内容保留 | 是，一键恢复 | 临时不用、排查同名冲突 |
| 删除 | `删除` | 删除本地技能及其资源文件 | 否（二次确认） | 自己新建 / 导入的本地技能 |
| 卸载 | `卸载` | 删除市场安装内容与安装记录，可选保留备份 | 仅备份可恢复 | 市场安装的技能 |

统一规则：

- 页面不使用笼统的「移除」作为按钮文案；必须落到上述三个动作之一。
- 删除与卸载必须二次确认，确认文案说明影响范围与是否可恢复。
- 停用必须可撤销，撤销后回到原分类与原位置。
- 系统内置技能三种动作都不提供，统一显示「Harness 自带，不能修改」。
- 诊断中的「删除失效项」属于「删除」的限定场景，文案必须带限定词，不能只写「删除」。

### 13.3 状态记忆与刷新

| 状态 | 记忆方式 | 何时重置 |
| --- | --- | --- |
| 当前一级 Tab | 本次会话 | 关闭面板后重开可回到「技能」 |
| 当前二级 Tab | 本地持久化 | 用户手动切换 |
| 搜索词 | 本次会话，切换 Tab 保留 | 用户清除或关闭面板 |
| 排序 | 本次会话 | 关闭面板 |
| 源顺序 | 本地持久化 | 用户拖动排序或使用 `Alt+↑` / `Alt+↓` |
| 列表滚动位置 | 本次会话 | 重新搜索、切换排序 |
| 详情返回位置 | 本次会话 | 返回列表后恢复 |
| 市场筛选与关键词 | 本次会话 | 关闭面板 |

刷新规则：

- 所有写操作（新建、编辑、停用、恢复、删除、安装、更新、卸载）成功后刷新当前视图，保留搜索、排序与当前二级 Tab。
- 打开页面、切回技能 Tab、手动 `检查更新` 时重新读取数据。
- 不假设外部文件改动会即时推送：用户在页面外改了技能文件时，允许页面显示旧数据；提供「重新检查」入口，并在诊断中反映最新扫描结果。
- 更新检查在后台进行，不阻塞列表；失败不弹错误提示，失败原因在「管理源」弹窗与诊断「来源不可达」中呈现，更新图标悬停提示仍显示上次检查时间。

### 13.4 权限与只读

| 场景 | 规则 |
| --- | --- |
| 系统内置 | 不显示编辑、停用、删除；需要说明原因，而不是把按钮藏到用户找不到 |
| 只读文件 | 操作按钮禁用并说明「这个文件不可写」 |
| 路径越界 | 拒绝写入，提示「目标位置不允许写入」 |
| 未授权 | 整页错误态 + 重试，不显示空列表冒充成功 |
| 服务未加载 | 显示「技能服务未加载」+ 说明，不显示空列表 |

### 13.5 跨模块一致性

- 技能名称、图标、描述在技能 Tab、详情、市场详情、诊断中保持一致。
- 市场安装后的技能在技能 Tab 中进入对应分类（二级 Tab）；来源以分组标题出现在技能列表，详情与诊断可再次说明，卡片内不重复源名。
- 分类名称固定为：我的技能、共享技能、项目技能、系统内置；任何页面不得使用其他别名。
- 页面不允许出现第二套位置语言（例如「用户级」「全局」「项目共享」）。

## 14. 文案规范

### 14.1 五条原则

1. **说人话**：用用户的动作和结果描述，不用实现机制。
2. **说影响**：告诉用户「会怎样」，例如「Agent 读不到它」。
3. **给动作**：每个问题至少有一个明确的下一步；按钮文案是动词。
4. **指名道姓**：使用技能名、位置名、源名，不用「该条目」「某项」。
5. **不责备**：不写「你配置错了」；写「这个文件需要一个名称」这类中性表述。

### 14.2 禁用词表

> **本节是实现备注**：左列词汇用于检索与走查，**不得出现在任何用户可见文案中**；右列是推荐替代。产品说明、实现备注、内部日志不在限制内，但不得截图进设计稿。

| 禁用词 / 概念 | 推荐说法 |
| --- | --- |
| rank、优先级数字 | 不表达；必要时说「当前生效的是『我的技能』里的版本」 |
| layer、层级、preset 层、全局层 | 我的技能 / 共享技能 / 项目技能 / 系统内置 |
| provider、filesystem、bundled | 本地文件 / 来自市场 / Harness 自带 |
| preset、预设可见性 | 不表达；用户侧只看四个分类 |
| 折叠分组、分组头、分组副标题 | 二级 Tab（我的技能 / 共享技能 / 项目技能 / 系统内置） |
| scope | 不表达；说「这个项目」或「所有 Agent」 |
| 遮蔽、覆盖链、同层 / 跨层 | 与另一个技能同名；当前生效的是哪一个 |
| commit sha、校验值、sha256 | 版本号（只显示市场版本） |
| 索引 format、schema 版本、校验规则编号 | 格式不正确 / 这个源读不了 |
| frontmatter、YAML、元信息字段名 | 文件开头的格式 / 技能文件格式 |
| 自定义根、custom root、安装根 | 不表达；路径只在详情「文件位置」与诊断「详细信息」出现 |
| 模型可用、用户可调用 | 不表达；技能能否被调用不作为管理信息展示 |
| 移除 | 停用 / 删除 / 卸载（三选一） |

### 14.3 允许出现的技术词

| 词 | 允许位置 | 说明 |
| --- | --- | --- |
| `SKILL.md` | 技能详情正文预览标题、新建 / 导入说明、诊断「详细信息」 | 作为文件名，不解释格式机制 |
| 完整文件路径 | 技能详情「文件位置」、诊断单条「详细信息」 | 不进入卡片、二级 Tab、状态图标提示 |
| 市场源 / 源 | 市场 Tab、管理源弹窗、技能 Tab 的来源分组组头、市场技能详情 | 唯一保留「源」概念的区域；组头只写源名与数量 |
| 版本 / 新版本 | 市场详情、更新提示、详情右栏 | 只显示市场提供的版本号 |
| 停用 / 恢复 / 删除 / 卸载 | 全局 | 语义见 §13.2，不混用 |

### 14.4 改写示例

> 反面示例仅用于对照走查，不得出现在界面。

| 场景 | 不要这样写 | 应该这样写 |
| --- | --- | --- |
| 同名冲突 | 「低优先级条目被遮蔽」 | 「`code-review` 与『我的技能』里的另一个技能同名，现在生效的是后者」 |
| 格式错误 | 「frontmatter 缺少 description」 | 「`my-skill` 的文件开头格式不对，Agent 读不到它」 |
| 链接失效 | 「symlink target not found」 | 「`tabbit` 指向的位置已经不存在了」 |
| 权限问题 | 「EACCES: permission denied」 | 「`team-skill` 所在的文件夹打不开，可能是权限问题」 |
| 来源错误 | 「索引 format 不支持」 | 「这个源暂时读不了，可以稍后重试或换一个源」 |
| 只读 | 「该位置不可写（E_READONLY_LOCATION）」 | 「Harness 自带，不能修改」 |
| 空列表 | 「暂无数据」 | 「还没有可管理的技能」+ 去市场看看 / 新建技能 |
| 更新失败 | 「更新失败」 | 「更新没完成：源连不上。可以重试，或稍后再检查」 |

### 14.5 数字、名称与占位

- 计数必须具体：`2 个技能未生效`，不写「有技能未生效」。
- 文案中的技能名保留可读空格；不要用文件扩展名代替技能名。
- 占位符统一用 `{name}`、`{count}`、`{version}`、`{source}`；中文句子中不留英文括号说明。
- 同类提示只出现一次：Tab 栏状态图标与卡片徽章分工明确，不重复完整句子。

## 17. 实现备注（非用户可见）

> 本节只供实现方与 Lead 对齐。以下术语属于内部机制，**不得进入界面文案、设计稿可见文字或 locale 字典**。

### 17.1 四个箱子与内部位置的映射

| 用户分类（二级 Tab） | 内部位置 | 默认路径 / 来源 | 可写 |
| --- | --- | --- | --- |
| 我的技能 | `user-dsh` | `~/.dsh/skills` | 是 |
| 共享技能 | `user-agents` | `~/.agents/skills` | 是 |
| 项目技能 | `project-dsh` + `project-agents` | `<项目>/.dsh/skills` + `<项目>/.agents/skills` | 是 |
| 系统内置 | `preset` + `bundled` | 预设包 / 插件包内技能 | 否 |

- 项目技能把两个内部位置合并为一个用户分类；分类内同名时由 `project-dsh` 胜出（rank 100 < 200），界面只表达「当前生效的是项目里的另一个版本」。
- 系统内置合并预设内置与插件内置；两者都只读，用户不需要区分。
- `custom` 目录不设独立分类，按可写性归属：只读的 `custom`（如预设包内挂载）归入系统内置；可写的 `custom`（用户自己配置的额外目录）归入「我的技能」，因为它同样是用户自己添加的技能来源。两种情况都不提供增删改入口，路径只在详情的「文件位置」与诊断里出现。
- 同名优先级只在内部用于判定「谁生效」；界面不显示 rank / layer / provider / 可见性矩阵。

### 17.2 状态与计数的内部口径

| 界面概念 | 内部判定 |
| --- | --- |
| 生效中 | 该技能是对应分类内实际被选中的条目 |
| 未生效 | 文件存在但被丢弃、被同名条目覆盖、不可读或格式不合法 |
| 已停用 | 文件位于 `.disabled/`，或等价的可恢复停用状态 |
| 有更新 | 安装记录版本低于市场源中兼容的新版本 |
| 来源不可达 | 市场源拉取失败；不影响已安装条目的可用性，不计入未生效 |

### 17.3 技术字段的保留位置

| 字段 | 界面 | 诊断「详细信息」 | 日志 / 状态文件 |
| --- | --- | --- | --- |
| 完整路径 | 详情「文件位置」 | 是 | 是 |
| rank / layer | 否 | 否 | 是 |
| provider / sourceType | 否 | 否 | 是 |
| commit sha / 校验值 | 否 | 否 | 是 |
| 预设可见性 | 否 | 否（只解释当前用户为什么看不到） | 是 |
| 索引 format / schema 版本 | 否 | 在源错误原因中可展开 | 是 |
